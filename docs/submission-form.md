## 4. Описание сведений о производительности и список реализованных дополнительных возможностей

```text
ПРОИЗВОДИТЕЛЬНОСТЬ (замеры на одном сервере 10 CPU, весь стек в Docker Compose, модель на CPU)
• Задержка «пакет NDTP → обработка»: p95 0,05–0,08 с в демо (30 ТС, поток ×30) и 0,15–0,24 с при нагрузке ×120 — при требовании < 1–2 с на ТС.
• Прогноз по всем ТС: тик (детектор, признаки, модель одним батчем) p95 ≈ 0,25 с раз в 30 с потока, инференс p95 75 мс.
• Без очередей: лаг Redis Streams 0–1 запись в демо, при ×120 до 37 и рассасывается за секунды; пропущенных тиков 0.
• Приём: ~2000 пакетов NDTP/с на одном приёмнике при 39 % одного ядра (≈ 24 000 ТС с пакетом раз в 12 с), 0 ошибок CRC и разбора.
• Память конвейера < 1 ГБ; холодный старт до healthy 10–13 с, первые прогнозы — в течение минуты.
• Надёжность: отказ приёмника NDTP, Redis, PostgreSQL, ML-сервиса или источника не роняет систему — последнее состояние с пометкой degraded, буферизация и дозапись без потерь, восстановление за 3–7 с; без ML прогнозы идут по резервной формуле. Проверка — make chaos.
• Каждый прогноз сверяется с фактом на потоке: онлайн-MAE 80,6 с против 127,3 с у baseline «отклонение сохранится» (4557 прогнозов дня test); все прогнозы выданы за 10–15 мин до плана, задним числом — 0.

ДОПОЛНИТЕЛЬНЫЕ ВОЗМОЖНОСТИ
• Ансамбль CatBoost + PyTorch GRU по последовательности телеметрии (обучение на GPU), экспорт в ONNX и квантование INT8 (веса в 3,7 раза меньше, точность та же).
• Интервалы P10–P90 (конформная калибровка, покрытие ~80 %), вероятность опоздания > 2 мин, вклад признаков (SHAP) → причина и рекомендация диспетчеру.
• Map matching: проходы остановок по GPS, линии маршрутов — привязка GPS-треков целых направлений к дорогам (OSRM match), без заездов к остановкам.
• What-if: резервный ТС или придержка — ожидание пассажиров, интервалы, опоздания, сбивки «до / после», подбор лучшего действия.
• Алерты уровня инцидента с гистерезисом и эскалацией, детектор сбивок ТС.
• График движения маршрута (план, факт, прогноз с P10–P90) и страница «Честность прогноза».
• Администрирование: поток, пороги риска на лету, версии моделей без остановки, дообучение на потоке (калибровка по закрытым прогнозам), журнал с CSV, здоровье сервисов.
• Prometheus (25 правил алертов) и 5 дашбордов Grafana, встроенных в дашборд.
• Два источника потока: исторический датасет как настоящий NDTP (replayer) и эмулятор организаторов.
• make submission повторяет сабмит (score 0,87636); CI; документация Sphinx + OpenAPI на GitHub Pages.
Подробно: https://github.com/DverkuOff/foresight/blob/v1.0/docs/performance.md
```

Откуда цифры: производительность и надёжность — [`performance.md`](performance.md) (§1, §3, §4), онлайн-MAE и
горизонт — [`online-validation.md`](online-validation.md) (§3), INT8 и интервалы — [`ml-report.md`](ml-report.md).
