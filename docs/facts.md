## 3. Протокол NDTP и эмулятор (проверено на живом эмуляторе)

- Кадр `[NPL 15][NPH 10][тело]`, little-endian — **совпадает со спецификацией**. `signature = 0x7E7E`, NPL `type = 2`,
  `peerAddress = unitId`.
- CRC-16/Modbus по NPH + тело, в NPL записан **со свапнутыми байтами** — подтверждено.
- Handshake: NPH `svc=0, type=100`, тело `(6, 2, flags=0, unitId, 65535, 0)`. Realtime: `svc=1, type=101`, `requestId` растёт с 1.
- Nav00: 26 байт `<IIIBBHHHHHBB>` (timestamp, lon, lat, флаги, bat, speedAvg, speedMax, course, track, alt, nsat, pdop);
  флаги `11100000` = valid + E + N. Идёт первой ячейкой. Заголовок ячейки — `[type u8][number u8]`.
- ⚠️ **Расхождение со спецификацией.** Значения ячеек в `POST /api/config` передаются как
  `{"type": "G6CellNav00", "fields": {...}}`. Плоские ключи рядом с `type` молча игнорируются (уходят нули).
- ⚠️ `timestamp` в Nav00 эмулятор всегда ставит сам (текущее время). Исторические метки через эмулятор не передать.
- ⚠️ Каждый `POST /api/config` рвёт соединения и открывает новые (новый handshake). Прогон трека через эмулятор =
  переподключение на каждое обновление конфига.
- `autoGenerate: true` + пустые `cells` → Nav00 (координаты около 55.70 / 37.50) + Usi08 + Termo16 + IntSensor02 + Can10.
- Irma04 (двери) доходит в пакете; точную раскладку байт брать из `GET /api/cells` при реализации парсера.
- Эмулятор стартует ~3 с, при недоступном сервере пишет WARN и повторяет подключение без падения.

## 6. Онлайн-проверка «поток = офлайн» (27.09, docs/online-validation.md)

- Весь день test через стек (replayer x60, модель v2-holdout — обучена только на train): онлайн-MAE **92.3 с** на 279 из 308 точек
  разметки, baseline `cur_dev_s` 98.1; 4339 прогнозов, lead 630–900 с, «задним числом» 0, fallback 0%, тик ≈ 116 мс.
- Та же модель офлайн: с онлайн-аналогом `cur_dev_s` (медиана трёх последних подтверждённых проходов) — 91.4; с `cur_dev_s`
  датасета — 78.0. Причина разрыва: **подсказка `cur_dev_s` в датасете в ~45% точек содержит факт, наступивший после T**
  (утечка будущего в данных организаторов). На потоке её нет — честная цифра системы ≈ 92 с при baseline ≈ 98 с.
- Алерты на уровне инцидента: 2547 → 237 (13.9 → 1.41 на инцидент), точность red ≈ 55%, полнота red 52%, хотя бы yellow 85%.
